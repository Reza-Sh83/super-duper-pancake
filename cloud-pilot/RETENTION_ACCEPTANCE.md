## Candidate limits and admission

- Free-space threshold 2,432,696,320 bytes includes the 2 GiB floor, 16 MiB writer headroom and the 256 MiB shutdown reserve.
- Strict admission with full W requires retained charge C + W < 5,100,273,664 and free F > 2,432,696,320 + W. At full W this means C < 4,563,402,752 and F > 2,969,567,232. The reserve is already in both thresholds. Recount after actual allocations and validate inclusive rejection at equality, and just inside/outside each strict boundary.
- Charge every file and directory at the greater of logical bytes and allocated blocks times 512, including retained inputs, existing partials and metadata. Bound simultaneous active raw, SQLite database/journal/temp, bounded compression output, archive staging and final, restore and replay work, logs and control receipts. Count both representations when they coexist. A verified same-filesystem rename avoids a second data extent, with metadata still charged. Treat unknown allocation, CoW or producer growth as a failed precheck.
- One common admission and allocation ledger for cooperating components, with no unrelated writer in the counted root. Enforce finite writer and namespace bounds before writes, including real SQLite, using fixed extents or synchronized enforceable allocations. A post-write census or polling watcher cannot supply the bound. Test concurrent contenders in both acquisition orders. The 512 MiB candidate is neither measured nor allocated by Manager.

## Manager evidence

`mgr-ret-tarxz-coexist-v1` used code `6fd6f6c`, the pinned Python environment and its existing sealed observe fixture. A real SQLite PERSIST/FULL journal was present and its transaction remained active through archive staging, publication and restore. The archive was 2,168 bytes. All five restored/source hashes matched, sealed replay passed and source/archive hashes were unchanged. Greater-of-logical-or-allocated charge was 106,496 bytes at staging, 155,648 immediately before commit/close, and 159,744 after commit/close. The 4,096-byte observed net change is neither a maximum transient nor a reserve bound. This probe used a 2 MiB per-file process limit with a fixed tiny fixture and bounded wall time. Full aggregate enforcement, truly simultaneous competing growth, refusal under overlap and reserve isolation remain the Implementer test targets. Temporary fixture outputs were cleaned and no process remains active.

An independent in-session review checked exact receipts, absence of a pinned derived codec in fetched refs, admission arithmetic and the need to account for staging, allocated extents, writer isolation and actual finalizer writes. This binding adopts those findings. No private input, remote store, paid service or pilot run was used.
