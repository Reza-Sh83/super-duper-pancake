## Hypothesis and policy

The rule succeeds on this exploratory sample only if OFI produces strictly higher paired validation-day net USD than both no-trade and static imbalance in **both** cost scenarios, with no safety violation. Use one frozen OFI policy, no fit, no threshold search. Treat a completed, covered comparison that misses a contrast as a miss. Use INCONCLUSIVE for invalid or nonmeasurable evidence. Baselines share input masks and execution rules, with independent accounts, depth consumption and risk state.

Process each complete atomic, valid BTC/USD depth-10 book update in capture receive-index order. Use the post-message top quote. Snapshot initializes state and contributes no transition. For successive quotes with bid price/size b/q and ask price/size a/r, event contribution is:
```
e = [b >= b_prev]*q - [b <= b_prev]*q_prev
    - [a <= a_prev]*r + [a >= a_prev]*r_prev
```
OFI score = sum(e) over the latest 20 valid update transitions divided by the sum, over those same transitions, of (q+r)/2 at the post-update quote. Include valid updates with unchanged top as zero contributions. Require all 21 quote states in one continuous READY epoch with oldest receive monotonic time at most five seconds before the current frame. Static control score = (q-r)/(q+r) at the same trigger. No-trade holds USD. Reset on invalid stream state, restore/restart, metadata version change, new epoch or split. Heartbeats are health evidence, never book events.

At the first eligible book update in each UTC receive second, each trading arm with no pending intent may use its own score. While flat and at least 60 seconds before exclusive end, enter long if score >= 0.20. Propose one buy for a 2.5%-of-current-NAV **fee-inclusive** maximum, subject to the approved risk engine and executable minima. No additional entry until flat. Exit if score <= 0 at the next eligible signal opportunity, at 10 seconds after first fill using a replayed monotonic timer (use the latest valid quote to form the intent), at end-minus-60-seconds, or on a risk exit, whichever fires first. Timer- and risk-triggered intents require a later book frame to fill. If invalid at exit due time, mark the exit due until the next valid quote. Once exit is due, keep the zero target across partials, and retry reducing under the contract. Never reverse or create a new entry intent in the same receive second as a terminal exit. Position still open at the end is disclosed with a valid liquidation mark if available, along with the unresolved exit. Never force an artificial boundary fill.

Diagnostics only: 10-second signed midpoint markout relative to the trigger quote for entry signals. Use the first strictly later valid book event with receive monotonic time in [trigger+10s, trigger+12s], same unbroken metadata and epoch, and within the same partition. Otherwise missing. Markout never affects any decision. Also report execution shortfall from decision midpoint, actual notional and fraction of displayed contra-side eligible depth, and latency distributions. Depth-10 prices, bounded consumer capacity and absence of passive orders constrain the result. Unknown queue position, hidden size and market feedback cannot be inferred.

## Clock, admission and chronological split

Manager names the first eligible pair of consecutive **complete UTC dates** in one separately authorized capture binding published before collection. First date is engineering development, second is sealed exploratory evaluation. A 48-hour capture with a partial UTC day cannot substitute. Neither date or required pre-start evidence may intersect the registered November/December studies or 180-day confirmation. Repeat admission only under a new preregistered study if fixed data fail. No carry or outcome-driven fitting between dates. Fresh $10,000 accounts, isolated feature state and no entries for the first 60 seconds of each day. Force exit intents from end-minus-60-seconds, clip matching at the exclusive end, and discard any derived sample whose feature-to-markout span crosses an edge. Reset both feature and trading state between distinct accounts. Record prior-session close evidence when necessary for operational criteria; never reuse prior-session features. If implementation needs an outcome-informed change, retire that date from evaluation.

Capture contract: sealed private raw public WebSocket v2 frames with source, hashes, connection epoch, receive index, receive UTC and monotonic clock, provider timestamp and checksum, validity/resync and loss/overflow records, timer/restart markers, bound metadata versions and independent clock evidence. Preserve exact Decimal text for checksums and replay; seal hash and verify canonical derived records against the raw stream. Require instrument status and tick/step/minima. Replay groups all deltas in one exchange message atomically. Never synthesize missing exchange timestamps or Kraken sequence numbers when absent. A CRC is an integrity check with limited scope, so combine it with local ordinal continuity, explicit drop evidence and snapshot-based resync. Capture data, private identities and detailed ledgers remain private.

Require the existing clock suite (including independent UTC samples, rechecks and monotonic-jump limits) and sealed replay integrity. READY coverage must be at least 99% of all UTC seconds, with p95/p99 book age <=1s/2s. Gaps count in the denominator. Never open or fill on a stale, future-dated, crossed, wrong-epoch or CRC-invalid book. At match use max age 2s, future tolerance 500ms, with the official offset/health conventions and WS silence/resync rules. Reject unavailable or invalid end NAV. Eligibility uses only information available by that event. Preserve input order, including equal timestamps. A future-suffix mutation must leave every earlier intent, reservation and feature byte-identical.

## Matching, accounting and verdict

Use immutable IOC limits from valid intent quote, buy floor_tick(ask*1.002) and sell ceil_tick(bid*0.998). Match only on the first valid book frame strictly later in receive order with monotonic time >= intent+latency and < intent+5s. Before applying the first eligible frame recheck TTL, metadata, risks and continuity. A received invalidation cancels the intent. Equal-to-limit depth after slippage is eligible. Walk only observable contra-side depth, debit the permitted quantity from arm-local level budgets and cancel the entire IOC suffix. Require executable minima and approved rounding. Base = observed spread/depth + 80 bp taker, 250ms. Stress = observed spread/depth + 100 bp taker, 1,000ms, and 10 bp adverse price adjustment with adverse tick rounding, still bound by the limit. Repeated levels cannot refill spent liquidity, and frame use must obey the approved level-revision carry and retry policies. The cash, BTC, fee and depth writes must reconcile atomically and replay identically. Keep the 10% total exposure cap, 1% day-loss lock and 4% high-water lock and all production readiness gates unchanged.

Per account report fills, filled/requested quantity, partials, expired/rejected counts and reasons, fees, turnover, spread/slippage diagnostics, realized USD, net USD and percent, sampled drawdown, exposure, coverage, skipped seconds, terminal BTC and exit fee reserve. Boundary mark uses the last valid bid known by exclusive end and valid at the boundary. NAV = cash + BTC*bid*(1-exit fee). Mark-to-bid is separate from realized P&L and from full-depth liquidation capacity. Net % = 100*(end NAV/10000-1) including all paid fees and estimated exit fee. Report all days and losses, including cross-arm paired differences. Use an explicit timestamped transaction log to reconstruct NAV and daily maximum drawdown. Measurable requires >=20 completed entry-to-flat episodes per trading arm per scenario in evaluation, complete boundaries and matching coverage. Publish all valid descriptive values even below this floor, alongside INCONCLUSIVE. One day gives no independent-day inference and cannot promote a strategy or verify the exploratory 50% objective by itself. A valid complete UTC day with >=50% modeled net is separately reviewed under the project's direct-data, execution and notification criteria.

## Code, tests and dispatch responsibility

Architect publishes a standard-library feature oracle and synthetic expected values, and reviews the exact replay and economics independently. Implementer binds this feature and timing contract to the existing CRC-verified book, risk and IOC ledger, supplies pinned commits, and runs synthetic tests before any real evaluation. Minimum acceptance includes snapshot + 20 updates, bid and ask direction, same-price changes, zero top transitions, exactly five seconds vs one tick late, epoch/gap purging, same-timestamp order, no-trade zero fills, immutable-prefix leakage, IOC at 249/250 and 999/1000ms, same-frame refusal, expiry at exactly 5s, inclusivity at limit after tick rounding, partial cancellation with exact fee and cash, depth reuse/reduction and min-size refusal, zero accounting effect on duplicates, and sealed prefix recovery. Compare the no-intervention canonical book transcript before introducing simulated orders. Test in the current guarded simulator or its offline equivalent. No external package or new feed is necessary for this unit.

Manager owns acquisition admission and the manifest (UTC dates, commits, data/checksum schema and coverage, first-availability/partition convention, instrument, fee and engine versions). Capture owns one authorized sealed data binding and handoff. Implementer executes the frozen comparison once only after input and prior-job verification. Architect reviews evidence. The existing 48-hour operational launch hold applies. No actual orders, paid runtime or main merge are authorized.

Do not evaluate DeepLOB, logistic or other learned models until this baseline is measurable and its identical replay and controls independently accepted. Any later model requires a separate preregistration, versioned weights and preprocessing, past-only fits and actual overlap purge, fresh disjoint prospective dates, same cost/depth/latency budget, and incremental paired net value versus this OFI baseline and both controls. The present one-day comparison cannot select a model.
